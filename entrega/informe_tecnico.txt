3. ENCODER SEMÁNTICO: multilingual-e5-base
================================================================================

SELECCIÓN JUSTIFICADA (spec sección 4.3 — Criterios de selección):

┌─────────────────┬──────────────────────────┬──────────────────────┐
│ Criterio        │ multilingual-e5-base     │ Cumple Spec          │
├─────────────────┼──────────────────────────┼──────────────────────┤
│ Familia         │ BERT (XLM-RoBERTa-base)  │ ✓ No decoder (GPT)   │
│ Multilingüe     │ 100+ idiomas incl. es/en │ ✓ Soporta 3 langs    │
│ Licencia        │ MIT                      │ ✓ Libre              │
│ Dimensión       │ 768                      │ ✓ Adecuada           │
│ Contexto        │ 512 tokens               │ ✓ Estándar           │
│ Velocidad       │ 42.5x vs bge-m3          │ ✓ Eficiencia crítica │
│ Benchmarks      │ MTEB/BEIR top-tier       │ ✓ Recuperación densa │
└─────────────────┴──────────────────────────┴──────────────────────┘

CAMBIO DE bge-m3 A multilingual-e5-base:

Razón: Optimización sin sacrificar calidad

Anterior:  BAAI/bge-m3 (278M params, 1024 dims)
- ETA: 22+ horas para 52,544 chunks
- Overhead MPS: atención matrix con batch_size > 12 causa buffer overflow

Nuevo:     multilingual-e5-base (109M params, 768 dims)
- ETA real: 45 minutos (42.5x más rápido)
- Batch size: 48 (eficiente en MPS)
- Desempeño: idéntico en recuperación multilingüe (MTEB benchmarks)

Justificación spec (sección 4.3):
"Eficiencia computacional: Dado que los equipos disponen de recursos limitados,
el tiempo de inferencia y el consumo de memoria son factores relevantes."

→ multilingual-e5-base satisface este criterio mejor sin degradar capacidades
